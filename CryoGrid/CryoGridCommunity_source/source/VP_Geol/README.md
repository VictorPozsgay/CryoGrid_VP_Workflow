# Carte géologique harmonisée GEO050K (BRGM)

## Overview

This workflow prepares geological datasets from the **Carte géologique harmonisée GEO050K (GEO050K_HARM)** produced by the BRGM (Bureau de Recherches Géologiques et Minières) for use in CryoGrid mountain permafrost simulations.

The workflow:

1. downloads the required BRGM department datasets,
2. merges geological polygons covering the French Alps,
3. builds the complete BRGM geological inventory,
4. rasterizes the original BRGM geological units onto the CryoGrid DEM grids,
5. builds a reduced inventory containing only geological units present in the modelling domain,
6. classifies the BRGM geological units into a reduced set of CryoGrid geological classes,
7. converts the original BRGM geological rasters into CryoGrid integer-class rasters.
8. builds the final CryoGrid mask,

The workflow preserves the traceability of every CryoGrid geological class back to the original BRGM `ID_original` and `NOTATION`.

The complete workflow is restartable: individual functions skip processing when their required outputs already exist.

---

## Data source

The workflow uses the official BRGM dataset:

**Carte géologique harmonisée GEO050K (GEO050K_HARM)**

The original data are distributed as department-level shapefiles containing geological formations represented as:

- polygon vector geometry,
- Lambert-93 projection (EPSG:2154),
- BRGM geological notation (`NOTATION`).

Only the departments required to cover the French Alps are downloaded.

## Workflow

Function: [`prepare_geology.m`](./prepare_geology.m)

The complete processing chain is executed with:

```matlab
prepare_geology(geology_path,dem_path)
```

where:

- **`geology_path`** (`..\CryoGridCommunity_forcing\geology`) is the root directory for geological products:

```text
CryoGridCommunity_forcing/
└── geology/
    └── BRGM_GEO050K_HARM/
        ├── raw/
        └── processed/
```

- **`dem_path`** (`..\CryoGridCommunity_forcing\DEM`) is the root DEM directory containing the resolution-specific products generated by [`prepare_dem.m`](/CryoGrid/CryoGridCommunity_source/source/VP_DEM/LiDAR_HD_DEM/prepare_dem.m):

For example:

```text
CryoGridCommunity_forcing/
├── geology/
│   └── BRGM_GEO050K_HARM/
│       ├── raw/
│       └── processed/
│
└── DEM/
    └── LiDAR_HD_DEM_10m/
        └── DEM/
            ├── DEM_massif_01.tif
            ├── DEM_mask_massif_01.tif
            ├── DEM_massif_02.tif
            ├── DEM_mask_massif_02.tif
            └── ...
```

The DEM resolution is selected using the optional `Resolution` argument:

```matlab
prepare_geology( ...
    geology_path, ...
    dem_path, ...
    "Resolution",10)
```

The default is:

```matlab
Resolution = 10
```

The corresponding DEM folder is determined automatically:

```text
dem_path/
└── LiDAR_HD_DEM_10m/
    └── DEM/
```

Only the `DEM_massif_XX.tif` files are used as target grids during geological rasterization.

The workflow also uses the DEM products to build the final CryoGrid mask. The final mask retains only pixels with valid:

- DEM elevation,
- slope,
- aspect,
- geology.

The mask is stored in:

```text
LiDAR_HD_DEM_10m/
└── MASK/
    ├── MASK_massif_XX.tif
    └── masking_log.mat
```

The workflow is fully restartable. Each processing step checks whether its output already exists and skips completed processing where possible.

# Processing steps

## 1. Download BRGM datasets

Function: [`download_BRGM.m`](./download/download_BRGM.m)

Downloads the required department shapefiles.

Current departments:

```text
04  Alpes-de-Haute-Provence
05  Hautes-Alpes
06  Alpes-Maritimes
26  Drôme
38  Isère
73  Savoie
74  Haute-Savoie
```

The downloaded files are preserved unchanged in `raw/`.

---

## 2. Merge geological polygons

Function: [`merge_BRGM_departments.m`](./processing/merge_BRGM_departments.m)

Combines all department shapefiles into a single Alpine dataset:

```
processed/BRGM_GEO050K_HARM_ALPES.mat
```

The merged dataset contains:

- polygon geometry,
- BRGM geological notation,
- geological descriptions,
- source attributes.

---

## 3. Build geological inventory

Function: [`build_BRGM_inventory.m`](./processing/build_BRGM_inventory.m)

Creates:

```text
processed/BRGM_GEO050K_HARM_inventory.mat
```

The inventory contains every geological unit present in the merged BRGM dataset.

Each unit is described by attributes including:

- `ID`,
- `NOTATION`,
- `DESCR`,
- number of polygons,
- total mapped area.

`NOTATION` is used as the geological-unit identifier because `CODE_LEG` is not unique across departments.

---

## 4. Rasterize geology

Function: [`rasterize_BRGM_geology.m`](./processing/rasterize_BRGM_geology.m)

Projects the geological polygons onto the CryoGrid DEM grids.

Outputs:

```text
processed/raster/
├── GEOLOGY_massif_01.tif
├── GEOLOGY_massif_02.tif
└── ...
```

Each raster:

- has the same grid geometry as the corresponding DEM,
- has the same spatial extent,
- uses the Lambert-93 projection,
- stores integer BRGM geological IDs,
- uses `-9999` as NoData.

The raster values correspond to the original BRGM `ID_original` values represented in the raster-domain inventory.

At this stage, the rasters still contain the **original BRGM geological identifiers**. No CryoGrid classification has yet been applied.

---

## 5. Build raster-domain geological inventory

Function: [`build_BRGM_raster_inventory.m`](./processing/build_BRGM_raster_inventory.m)

Creates:

```text
processed/BRGM_GEO050K_HARM_raster_inventory.mat
```

This reduced inventory contains only geological units that actually occur within the CryoGrid modelling domain.

The important identifier is:

```text
ID_original
```

which provides the link between the raster value and the original BRGM geological unit.

Some geological units present in the complete BRGM inventory are absent because they occur only outside the Alpine modelling domains.

The original complete inventory is preserved separately.

---

## 6. Classify BRGM geological units

Function: [`classify_BRGM_geology.m`](./processing/classify_BRGM_geology.m)

This is the **scientific geological classification step**.

It uses the raster-domain BRGM inventory:

```text
processed/BRGM_GEO050K_HARM_raster_inventory.mat
```

and the classification rules defined by:

```text
BRGM_CryoGrid_rules.m
```

The classification assigns every BRGM geological unit to one of the following CryoGrid classes:

```text
0      UNKNOWN
1      BEDROCK
2      SEDIMENT
3      TILL
4      SCREE
5      ICE
6      ORGANIC
7      WATER
```

The value:

```text
-9999
```

is reserved for NoData in raster products.

### Classification logic

The classification uses two complementary sources of evidence.

#### 1. Exact `NOTATION` rules

Exact BRGM geological notations defined in the classification rules have absolute priority.

#### 2. Keyword rules

Keywords are searched in the BRGM geological descriptions.

Keyword strength is ranked as:

```text
STRONG > WEAK
```

When multiple classes have equally strong evidence, the order defined by:

```text
RULES.CLASS_ORDER
```

determines the final class.

All triggered classes and rules are retained in the classification diagnostics.

### Matching

Keyword matching is:

- case-insensitive,
- accent-tolerant,
- tolerant of the BRGM encoding-corruption character `�`,
- substring-based,
- compatible with multi-word keywords.

Nested keyword matches within the same text word are reduced to the longest matching keyword.

Known false-positive strings can be removed using the exclusion rules defined in:

```text
RULES.EXCLUDE
```

### Classification outputs

The function writes two products to:

```text
processed/
```

#### Classification log

```text
BRGM_CryoGrid_classification_log.txt
```

The log contains:

- scientific input information,
- classification rule information,
- classification statistics,
- unknown-unit diagnostics,
- trigger statistics,
- a complete unit-by-unit classification record,
- multiple-trigger diagnostics,
- unclassified-unit diagnostics.

#### Classification index

```text
BRGM_CryoGrid_classification_index.mat
```

This is the persistent scientific mapping used by the next workflow step.

The saved index contains:

```text
ID_original
NOTATION
CRYOGRID_CLASS
CRYOGRID_CODE
METADATA
```

The `METADATA` field explicitly documents the numerical coding:

```text
0     = UNKNOWN
1     = BEDROCK
2     = SEDIMENT
3     = TILL
4     = SCREE
5     = ICE
6     = ORGANIC
7     = WATER
-9999 = NoData
```

This index is the interface between the scientific geological classification and the final raster products.

Importantly, the classification does **not** need to be rerun when only the raster conversion is required.

---

## 7. Convert BRGM rasters to CryoGrid geology rasters

Function: [`raster_conversion.m`](./processing/raster_conversion.m)

This is the final raster-production step.

It does **not** perform geological classification.

Instead, it consumes:

```text
processed/BRGM_CryoGrid_classification_index.mat
```

and applies the fixed mapping:

```text
BRGM ID_original  →  CryoGrid integer code
```

to every original BRGM geological raster.

Input:

```text
processed/raster/
├── GEOLOGY_massif_01.tif
├── GEOLOGY_massif_02.tif
└── ...
```

Output:

```text
processed/raster_CryoGrid/
├── GEOLOGY_massif_01.tif
├── GEOLOGY_massif_02.tif
└── ...
```

The output raster therefore contains CryoGrid geological class codes rather than the original BRGM IDs.

### CryoGrid raster coding

| Code | Class |
|---:|---|
| `0` | `UNKNOWN` |
| `1` | `BEDROCK` |
| `2` | `SEDIMENT` |
| `3` | `TILL` |
| `4` | `SCREE` |
| `5` | `ICE` |
| `6` | `ORGANIC` |
| `7` | `WATER` |
| `-9999` | NoData |

The original BRGM rasters in:

```text
processed/raster/
```

are never modified.

The converted rasters in:

```text
processed/raster_CryoGrid/
```

are therefore derived products and can always be regenerated from:

```text
processed/raster/
```

and:

```text
processed/BRGM_CryoGrid_classification_index.mat
```

without repeating the scientific classification.

---

## 8. Build final CryoGrid mask

Function: [`build_final_mask.m`](./processing/build_final_mask.m)

The final mask is generated for each massif by combining the validity of:

- the original DEM,
- slope,
- aspect,
- geological raster.

A pixel is retained only if all four products contain valid data.

The resulting masks are saved in:

```text
LiDAR_HD_DEM_10m/
└── MASK/
    └── MASK_massif_XX.tif
```

A:

```text
masking_log.mat
```

records the number and percentage of pixels removed by each masking criterion.

# Scientific traceability

The workflow maintains the following chain:

```text
BRGM geological polygons
        │
        ▼
BRGM geological inventory
        │
        │ ID_original
        ▼
BRGM raster
GEOLOGY_massif_XX.tif
        │
        │ ID_original
        ▼
BRGM_CryoGrid_classification_index.mat
        │
        │ CRYOGRID_CODE
        ▼
CryoGrid geology raster
GEOLOGY_massif_XX.tif
```

The key principle is that the scientific classification and the raster conversion are separate operations.

The classification is performed on the geological-unit inventory, not independently for every raster pixel.

Once:

```text
BRGM_CryoGrid_classification_index.mat
```

has been created, the geological rasters can be converted without rerunning the classification rules.

# Output usage

## Original BRGM geological raster

The original BRGM raster can be loaded with:

```matlab
[GEO,R] = readgeoraster( ...
    "GEOLOGY_massif_01.tif");
```

Its values correspond to `ID_original`.

These IDs can be linked to the raster-domain geological inventory:

```text
BRGM_GEO050K_HARM_raster_inventory.mat
```

or to the complete BRGM inventory:

```text
BRGM_GEO050K_HARM_inventory.mat
```

---

## CryoGrid geological raster

The final CryoGrid raster can be loaded with:

```matlab
[GEO,R] = readgeoraster( ...
    "GEOLOGY_massif_01.tif");
```

from:

```text
processed/raster_CryoGrid/
```

Its pixel values are directly interpretable using the CryoGrid coding:

```text
0     UNKNOWN
1     BEDROCK
2     SEDIMENT
3     TILL
4     SCREE
5     ICE
6     ORGANIC
7     WATER
-9999 NoData
```

Because the converted raster uses the same spatial grid as the original BRGM raster, it remains aligned with the corresponding DEM and other spatial products.

# Restartability

Every stage is designed to be restartable.

In particular:

- the download step preserves already downloaded BRGM data,
- intermediate inventories are not rebuilt unnecessarily,
- geological rasters are not regenerated when their outputs already exist,
- the final mask is skipped when its required products are already present,
- the scientific classification is skipped when both of its output products already exist:
  - `BRGM_CryoGrid_classification_log.txt`
  - `BRGM_CryoGrid_classification_index.mat`
- raster conversion is skipped when the output directory exists and contains the corresponding converted raster for every original raster.

This allows the complete `prepare_geology` workflow to be rerun safely after interruption.

# Notes

- Raw BRGM data are never modified and remain stored in `raw/`.
- Intermediate products are stored in `processed/`.
- Original BRGM geological rasters are preserved in `processed/raster/`.
- Final CryoGrid geological rasters are stored separately in `processed/raster_CryoGrid/`.
- The scientific classification is performed at the geological-unit level rather than independently for each raster pixel.
- `ID_original` provides the traceability from raster values to the original BRGM geological unit.
- `BRGM_CryoGrid_classification_index.mat` is the persistent interface between the scientific classification and raster conversion.
- Raster conversion does not rerun the classification rules.
- `-9999` is reserved for NoData and is not a geological class.
- Every processing stage is restartable.
